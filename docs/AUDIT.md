## Actual package structure

StreamClipper is a Python package under `src/streamclipper` with a CLI,
dashboard HTTP server, VOD and live pipelines, local state, publishing
helpers, HUD analysis, face tracking, and CapCut draft/render tooling.

Important modules:

- Discovery and unified scoring: `discovery.py`, `scoring.py`, `story.py`
- Audio, speech and chat: `audio.py`, `asr.py`, `chat.py`, `llm.py`
- Gaming HUD: `hud/`, `hud/analyze.py`, `hud/detect.py`, `hud/frames.py`
- Face and layout: `faces.py`, `vision.py`, `layout.py`
- Live processing: `live/`
- Rendering and quality: `render.py`, `gate.py`, `captions/`
- Dashboard: `dashboard/`
- Publishing: `publish/`
- Brand and copy: `brand.py`, `copywriter.py`, `captions/styles.py`
- Persistence: `state.py`, `paths.py`, `dashboard/jobs.py`

## Existing equivalents

### Static screen and advertisement quality

No dedicated static-screen module exists. Export quality currently checks
rendered MP4 audio, captions, and faces. There is no source-video motion map,
static interval overlap, or static penalty in candidate discovery.

Integration point: `src/streamclipper/discovery.py` plus
`src/streamclipper/scoring.py` and a new quality module.

### Game-aware intelligence

Partial support exists:

- HUD profiles exist for GTA V, experimental GTA VI, and generic games.
- The LLM prompt is gaming versus podcast/talk and asks for story moments.
- Copy generation detects GTA 6 heuristically and generates category/keyword
  tags.
- Hooks are generated by transcript and category logic.

Missing:

- A unified game registry independent of HUD profiles.
- Extensible aliases and game-specific event taxonomy.
- Game-specific prompt context and hook profiles.
- Configurable 2-5 word hook style.

Integration point: a new `games.py` module used by discovery, copy generation,
the LLM prompt, and dashboard options.

### Unique audience reaction detection

Partial support exists:

- Chat replay parsing supports YouTube, Twitch rechat, and JSONL.
- Chat is bucketed into message rates and hype ratios.
- Candidate windows call `window_score()`.

Missing:

- Distinct usernames.
- Normalized user identifiers.
- Unique reaction windows.
- Chat acceleration and bounded rolling state.
- Spam/repetition penalties.
- Anonymous chat fallback is effectively message-based, but live Twitch/YouTube
  parsing does not currently retain username data.

Integration point: extend `src/streamclipper/chat.py` and
`src/streamclipper/live/chat.py`, while preserving the existing chat dict shape
at scoring boundaries.

### Facecam detection

Existing support is substantial:

- MediaPipe BlazeFace with tiling and Haar fallback.
- Smoothed face tracks, face size, active-speaker selection.
- Corner/full/no-cam classification.
- Fixed overlay border snapping.
- Manual `--cam-crop` overrides.
- Safe full-frame fallback for unrecognised layouts.

Missing:

- A dedicated static-border/facecam-fusion module that combines persistent
  rectangles with face evidence and exposes confidence diagnostics.
- Method 1 is partly present in `vision.snap_to_overlay`, but it is not a
  generalized persistent-border facecam detector.

Integration point: add a facecam quality/fusion module and reuse
`faces.py`, `vision.py`, and `layout.py`.

### Publishing scheduler

Existing support is already substantial:

- YouTube OAuth and resumable upload with refresh and scheduling.
- Instagram Reels credentials and upload.
- TikTok publish pack/export fallback.
- Dashboard single-clip publish and Schedule week.
- Redacted private token storage.
- Mocked API tests and basic upload retries.

Missing:

- Multi-account model.
- Persistent queue independent of each clip's `publish` field.
- Multiple platform targets for one clip.
- Configurable interval and per-platform daily limits.
- Bounded exponential backoff.
- Publishing history and retry queue across dashboard restart.
- TikTok direct publishing is intentionally not implemented because app review
  and API eligibility are external constraints.

Integration point: extend `publish/store.py`, `publish/schedule.py`, and
`dashboard/publishing.py` before adding a broad scheduler service.

### Multi-creator workspaces

Not present. The dashboard uses one workspace and stores jobs beneath one
`workspace/jobs.json` index.

Existing isolated data surfaces:

- Workspace brand kit.
- Workspace settings.
- Jobs and deleted/mark state.
- Publishing credentials in global per-user config.

Missing:

- Creator registry and stable creator IDs.
- Job/clip/queue/brand/publishing ownership.
- Safe migration to a default workspace.
- Creator-specific settings isolation.

Integration point: lightweight `creators.py` plus workspace metadata and
job fields; no database or multi-tenant framework is required initially.

## PeakCut feature integration matrix

| PeakCut capability | StreamClipper equivalent | Decision |
|---|---|---|
| Static-screen analysis | None | Add dedicated quality module |
| Game registry and prompt context | GTA HUD profile plus GTA heuristic copy | Add unified game registry, preserve HUD |
| Unique chat usernames | Message/hype rate chat signal | Extend parsers and live chat |

| Setup/payoff scoring | Existing story-first scoring | Integrate signals, do not add engine |

## Unified scoring integration

The existing `score_parts()`/`combine()` architecture is the correct integration
point.

New signals must be added as components or explainable signals in the existing
flow:

- Static quality: quality decision/rejection and a bounded static penalty.
- Game awareness: game-specific event/context weights and metadata.
- Unique chat: augment `chat.score` and ratio; do not double-count raw message
  and unique chat components.
- Facecam: face motion stays optional and weak; it must not override strong
  audio/visual evidence.
- HUD: existing `hud` component is retained and is not replaced.

Candidate `clips.json` entries should continue to expose `breakdown`, `reason`,
`signals`, `sources`, `category`, and setup/payoff segment metadata.

## Dependency and data-model audit

Current dependencies:

- Python `>=3.10`
- NumPy
- yt-dlp
- streamlink
- optional faster-whisper
- optional MediaPipe/OpenCV/ONNX runtime

No dependency conflict is expected for the static-screen phase. It uses FFmpeg
and NumPy only.

Potential implementation dependencies:

- No third-party game or creator database package is needed.
- Publishing queue state will remain JSON in the workspace/config for now.
- Creator metadata will be JSON in each workspace.
- OAuth refresh tokens stay private in `STREAMCLIPPER_CONFIG_DIR`.

State/data changes expected:

- `clips.json` and candidate dictionaries gain static/game/chat/face
  diagnostics.
- `RunState` gains a quality stage.
- Dashboard jobs gain optional `creator_id`.
- Jobs not carrying `creator_id` migrate to `default`.
- New workspace files: `creators.json` or `creators/<id>/creator.json`.
- New publishing queue: workspace or config JSON with platform/account/job/
  clip keys and status.

No schema migration framework is needed for the initial lightweight design.
Readers will use defaults and explicitly migrate legacy records.

## Implementation status

### Feature A — static-screen quality

Added `src/streamclipper/quality.py`:

- FFmpeg `tblend`/`signalstats` motion map.
- Configurable bucket, threshold and minimum static duration.
- Cached motion/static ranges in run state.
- Candidate overlap, overlap percentage, motion score and quality decision.
- Dominated static candidates are rejected; partial static overlap is penalised.
- CLI flags: `--static-analysis`, `--static-bucket`, `--static-min`,
  `--static-threshold`.

### Feature B — game-aware intelligence

Added `src/streamclipper/games.py`:

- Extensible game registry.
- GTA VI profile as the highest-priority GTA alias.
- Game aliases, event taxonomy, tags and contextual hooks.
- Manual `--game` override.
- Generic gaming fallback.
- Game context supplied to LLM prompts and game tags supplied to copy
  generation.

### Feature C — unique audience reactions

Extended `src/streamclipper/chat.py` and `live/chat.py`:

- Optional normalized username/ID-aware replay and live chat.
- Distinct usernames per second and unique-user baselines.
- Rolling/repetition/spam indicators.
- Anonymous/missing-identity fallback to existing message-based scoring.
- Candidate signals include `chat_unique_ratio` and `chat_spam`.

### Feature D — hybrid facecam detection

Added `src/streamclipper/facecam.py`:

- Persistent horizontal/vertical border geometry candidates.
- Fusion with existing MediaPipe/Haar face evidence.
- Conservative confidence and diagnostic evidence.
- Manual crop override preserved.
- No-camera and low-confidence fallback does not force split layout.

### Feature E — publishing scheduler

Added `src/streamclipper/publish/queue.py`:

- Persistent scheduled publishing queue.
- Duplicate upload prevention.
- Per-platform interval and daily-cap scheduling.
- Bounded exponential retry backoff.
- Published, failed, cancelled and export-pack histories.
- Dashboard queue/account surfaces.

Existing YouTube OAuth, Instagram credentials and TikTok export-pack code remain
the publication backends.

### Feature F — creator workspaces

Added `src/streamclipper/creators.py`:

- Default personal workspace.
- Isolated creator settings.
- Safe migration of existing jobs to `default`.
- Deleting a creator migrates jobs back to `default` and never deletes media.
- Dashboard creator selector and creator APIs.

## Data-model changes

- Run state gains a `quality` stage.
- Clip documents can carry `quality`, `game`, `chat_unique_ratio`,
  `chat_spam`, and facecam diagnostics.
- Job records gain `creator_id`; existing records migrate to `default`.
- New workspace file: `creators.json`.
- New workspace file: `publish_queue.json`.
- Account registry: `publishing_accounts.json` in
  `STREAMCLIPPER_CONFIG_DIR`; tokens remain in the existing private token files
  and no token value is stored in queue entries.

## Known limitations

- Static thresholds are initial starting values and still require calibration
  against representative ads, BRB, menus, loading, gameplay pauses and mixed
  moments.
- GTA VI remains an experimental profile until calibrated with authorised
  GTA VI footage.
- Facecam detection is conservative; detection accuracy cannot be guaranteed
  and no 100% accuracy claim is made.
- TikTok direct automated publishing is not assumed; export-pack fallback
  remains valid because app review/account eligibility is external.
- The mocked publishing tests prove request/queue behavior; real OAuth app
  approval, API review, rate limits and platform eligibility still require
  account-specific validation.
